# 006 · 设置布局与窗口交互设计

## 2026-09-22 修复：企业微信的指定应用保护被装饰窗口拦截

只读检查确认已保存的企业微信规则开启启动与跨屏移动；主窗口 WeWorkWindow 可见、非透明、无所有者，但还拥有同进程的 TitleBarWindow（标题栏）和 PerryShadowWnd（阴影）。旧 ScreenApplicationService 对任何可见附属窗口直接失败，因此在移动主窗口前就保留幕布，且仅返回通用原因。

修复在应用窗口访问层增加仅用于本次枚举的进程、扩展样式、DPI 元数据，用独立 ApplicationWindowFamilyPolicy 识别企业微信装饰。必须同时满足 WXWork.exe／WeWorkWindow、同一进程和路径、直接所有者关系、不可激活的分层工具窗口样式，以及标题栏顶部窄条／阴影紧邻主窗口的几何约束；不把任意附属窗口或仅同类名窗口放行。最小化其他窗口时排除主窗口及已复核装饰；每次枚举与最小化前重新核对，撤幕前再次复核，新增弹窗、身份变化或无法读取仍保留幕布。

不改变精确窗口选择、多窗口歧义、启动／跨屏授权、完整覆盖、先隐藏其他窗口再撤幕的规则。增加各失败阶段的明确中英文状态及不含路径、标题、窗口身份的固定原因日志。配置 schema 不变，不改真实配置。回滚仅撤销窗口族识别与失败说明，恢复原来的保守幕布行为。

状态：用户已确认，WPF 客户端已实施并通过自动化验证。关联 [006 开发计划](006-settings-layout-plan.md)。

## 目标与上下文

用户反馈标题栏最大化图标不随状态变化、普通窗口拖动失效，设置页面层级混乱。沿用已确认静绿配色、A+ 叠屏静夜图标、中英文和独立配置，先用 baoyu-design 制作可点击原型，设计确认后再进入客户端实施。

## 方案

- 左侧固定显示器列表：编号、主屏标识、已保存管理状态、未保存标记；底部刷新及通用设置。
- 右侧顶部显示当前屏幕、管理开关和已生效状态；屏幕休息为第一个且默认打开的页签，隐私保护为第二个。编辑只影响草稿；切换屏幕、页签、语言保留草稿。
- 隐私保护：关闭/隐私幕/回到桌面/指定应用，独立等待时间，醒来后的结果说明；暂缓作用于已保存且启用的当前屏幕。
- 屏幕休息：不休眠/遮黑/调暗；根据选择展示等待、亮度和唤醒条件。保留现有校验：启用管理不能同时关闭隐私并选择不休眠。
- 已生效规则与当前草稿分开显示；底部固定放弃/保存全部设置，失败保留草稿。全局立即保护只使用保存过的规则。
- 通用设置：语言与开机启动、产品信息；原型仅模拟，不能改变系统或配置文件。
- 标题栏状态图标随普通/最大化切换，空白可拖动，双击切换状态，最大化向下拖动还原。浏览器只能模拟应用窗口，不能验证真实 WPF 原生行为。
- 正常窗口约 1040×700，窄窗口 700×500；最大化模式扩展工作区但限制表单行宽。增加空屏、加载、失败、不支持调暗和保存失败的演示场景。

## 第二轮交互调整

- 隐私等待使用数值＋秒/分钟/小时；暂缓默认时长使用数值＋分钟/小时，可在隐私设置中保存，也可在点击暂缓时调整。时间均校验正整数，隐私等待和暂缓上限为 24 小时。
- 当前屏幕标题区新增“应用到其他屏幕”。弹窗选择全部其他屏幕或指定屏幕，展示来源和覆盖范围；复制当前草稿的屏幕休息、隐私、暂缓及幕布图片设置，目标屏幕的管理开关保持原样。目标草稿会被覆盖，但先不生效，仍需底部保存；可统一放弃。目标不支持调暗时明确提示并改为遮黑。演示增加第三块屏幕以区分全部与指定。
- 隐私幕外观：默认纯色或自定义图片。默认幕布和图片幕布都只展示“继续使用此屏幕”按钮，无图标、标题和说明。屏幕保护预览用完全不透明的背景覆盖模拟窗口。
- 自定义可选择一张或多张 PNG/JPEG/WebP 图片，支持缩略图删除、铺满/完整显示，多张按顺序循环并可设切换间隔。提供本地 SVG 示意图库方便评审；图片读取失败时回退纯色，按钮保持可用。
- 图片只在浏览器中读取，不上传、不持久化；选择文件时绑定当时的来源屏幕，避免异步读取期间切屏写错目标。图片为空时阻止保存自定义方案，保留草稿。正式客户端图片存储、迁移与文件丢失恢复留待实施设计。

## 指定应用（第三轮，已确认）

- 隐私方式新增第四项“指定应用”，常规窗口四列，700×500 两列。选择运行窗口或填写 Windows 程序路径；运行窗口列表全部为虚构示例，可搜索、确认或取消，不枚举真实窗口、不读取标题、不启动程序。
- 手动添加接受本地绝对 .exe 路径，原型只校验格式，不能检查安装或启动能力。不含脚本、命令行参数、浏览器 URL/网页标签定位或商店应用发现。
- 未运行时默认保留隐私幕，可选择启动程序；在其他屏幕时默认保留隐私幕，可明确允许移到目标屏幕。不静默任选同进程窗口，不重复启动已运行程序。权限不足或无法确定窗口时保留隐私幕。
- 保护顺序：先遮挡目标屏幕，再隐藏其原窗口、定位/启动所选应用，确认窗口覆盖该屏可见区域后才撤幕。醒来显示所选应用，不自动还原原窗口。选择界面说明应用原有内容不会清空，需选可公开展示的窗口。
- “测试切换”提供正常、未运行、其他屏幕、多窗口、启动/切换失败场景。成功展示虚构应用画面；失败解释原因并提供纯按钮隐私幕预览。实际 Windows Z 序、置顶窗口、DPI、启动等待及不抢占其他屏幕输入焦点的可行性，留待客户端验证。
- 应用、窗口标识及处理偏好参与草稿、保存、放弃及跨屏复制。同一目标窗口被多个已启用屏幕选用时阻止保存，提示重新选择；复制弹窗说明同一窗口不能同时显示在多屏。
- 与前两轮布局、时间、图片和复制设置一起评审；整体确认后再补客户端实施步骤与兼容迁移设计。本轮不修改客户端或真实配置。


## 客户端实施决策

- 扩展 schema 1 的可选 PrivacyOptions，保留 PrivacyMode 0/1/2 和 PrivacyIdleSeconds；指定应用新增为 3。旧配置默认纯色、15 分钟暂缓。新增字段参与草稿、验证、复制、保存及回退。
- 应用选择仅在用户打开选择器时读取标题供显示，不持久化或记录标题。保存 exe 路径和窗口类；本次会话精确绑定选择的窗口，重启后仅唯一匹配才执行，多窗口不猜测。启动仅允许本地 exe，无参数/脚本。
- 应用操作继续先显示不透明幕布，目标窗口完整覆盖本屏、其他窗口已安全隐藏并完成复核后才撤幕；跨屏窗口、附属窗口、无法确认的窗口保留幕布。移动与启动分别要求已保存的显式选项。
- 图片导入复制到本产品 PrivacyImages 目录，以随机不可变名称保存；先验证并完成导入再引用，不覆盖旧图，不自动删除未引用图片，配置失败/放弃可恢复原引用。限制 12 张、每张 10 MB，解码失败保持纯色遮挡。
- 暂缓只修改计时，不解除现有幕布；保存新默认时长不重置正在进行的暂缓。
- 验证包括模型兼容/草稿/批量、窗口失败与取消、图像加载与不透明幕布、WPF 最小尺寸/英文、完整构建和测试。回滚可恢复客户端源文件及配置备份；新增字段是可选扩展，回退前关闭指定应用模式。


## 已实施边界与核验

- `WindowChrome` 接管标题栏的移动/双击/还原，去除透明无边框窗口的自绘拖动；语言、按钮等区域显式设为客户端命中区。
- 应用窗口访问由 `IApplicationWindowAccess` 隔离，原生定位使用不激活和异步请求，随后验证位置及其他窗口消失，不把 API 返回值当作覆盖成功。参考 [Microsoft SetWindowPos](https://learn.microsoft.com/windows/win32/api/winuser/nf-winuser-setwindowpos)。
- 只有精确会话身份或重启后唯一的 exe/窗口类匹配才操作；不把关闭的已选窗口替换为同程序的其他窗口。匹配进程已运行但无可用窗口时不重复启动。重启后无法区分的多屏同应用规则回退幕布，需重新选择具体窗口。
- 图片由 Windows WPF 解码器导入后统一写为 PNG；PNG/JPEG 可直接导入，WebP 依赖系统安装的解码器，缺失时给出导入失败说明。拒绝超过 10 MB、4000 万像素的来源图，不引用原图路径。读取失败回退纯色。移除/放弃不删除已导入文件，暂不自动清理孤立图片。
- 指定应用的启动可能受应用自身启动行为影响；第三方程序的后续弹窗、独占全屏、安全桌面和混合 DPI 不属于本次自动化测试覆盖范围。功能不是访问控制边界。
- 原型保留为评审记录。客户端使用真实窗口/文件选择器，不带模拟场景选项；本轮不构建安装包，不修改既有已安装实例，不提交或推送。
