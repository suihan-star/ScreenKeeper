# 012 · 设置直接展示与色温恢复入口修正

承接 [008 布局设计](008-app-layout-design.md)、[010 色温设计](010-color-onboarding-design.md)，实施见 [012 计划](012-settings-recovery-plan.md)。

## 用户确认范围

- 隐私保护的更多设置直接展示，上下使用分隔线。
- 健康提醒／提醒节奏删除「工作与休息」标题；时长与减少打扰之间加分隔线；更多设置直接展示，与上方分隔。保持保存、时长和运行周期行为。
- 排查 DELL 无法验证及重新建立原色确认框不可选，说明验证用途并消除恢复死结。

## 色温问题与修正

只读证据：已保存两屏调色均关闭；仅 AOC Q27P10 有旧恢复记录。两屏当前均 SDR 扩展、Gamma 可读；AOC HardwareId 与物理 ScopeId 匹配，但当前拓扑／模式指纹与旧记录不同。旧的重建流程也要求旧模式完全相同，导致连接变化后无法生成确认凭证，复选框禁用；全局恢复记录又阻止 DELL 试验。不能认定 DELL 硬件不支持。

保留首次人工观察验证：确认目标变化、其他屏幕不变及恢复正常。保留有未解决恢复记录时不开展新硬件试验的规则，因为试验也需要读其他屏幕基线并检测连带影响。优化说明和入口，不让用户猜测禁用原因。

仅在不写设备的「重新建立原色」流程允许旧模式变化：旧记录与当前能力必须唯一匹配 HardwareId 和物理 ScopeId，当前须 SDR 扩展、可读取；采集当前精确作用域与颜色，两次复核稳定，再显示需要人工确认的屏幕。确认时继续复核当前精确作用域／颜色、设置、期限与记录未变；先耐久归档旧记录，再撤销资格、写入强制重新验证标记。实际调色、旧原色恢复和普通「重新检查原色」仍要求原精确作用域，绝不把旧 Gamma 写到新连接／新模式。

验证弹窗显示待处理屏幕及就地处理入口；重建弹窗仅在检查成功后展示可勾选的观察确认，不以灰色复选框代替失败原因。检查失败显示原因、重试及返回入口。范围不含自动归档用户记录、代替人工确认、取消校色／HDR 门禁或实机写色。

## 备份失败补修（2026-09-22）

用户实测确认后出现“旧原色记录备份失败”。根因是 `ColorRecoveryFileStore.TryArchive` 仍对旧记录和当前观察执行 `SameScope` 精确比较，与前述允许同屏连接／模式变化的只读重建规则冲突。上次服务测试使用模拟恢复存储，实机探针只执行准备阶段，未覆盖真正存储层的确认链路。

归档是审计证据，不执行设备写入：旧记录和新观察允许模式／拓扑／临时设备地址不同，但必须按非空 HardwareId 与物理 ScopeId 唯一一一对应，新观察的当前完整作用域和颜色必须有效。分别原样保留旧作用域／颜色与新观察，不把新作用域覆盖到旧记录。实际写设备与确认时的精确作用域复核保持不变。

补充生产恢复存储、设置文件存储及真实临时磁盘的集成测试，覆盖确认成功后归档可读、旧资格撤销、活动记录退役及强制重新验证标记；模拟设备全程不得写入。另验证身份不符、重复／缺失观察、无效作用域、磁盘写入失败仍不解除保护。真实用户配置仅只读，不代替用户完成归档或验证。

## 验证与回滚

使用模拟后端覆盖旧模式已变但同物理屏幕的准备与确认、其他物理屏幕／身份冲突／未连接／HDR／复制拒绝、确认期间再次变化、归档失败；断言全流程零设备写入。复用 WPF 中英文、两主题、标准与 700×500 布局核验；修改的弹窗核验阻塞／可确认／完成状态。回滚只撤销本次增量，无配置 schema 迁移，真实记录保持不动。
