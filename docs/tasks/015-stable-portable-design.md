# 015 · 1.0.0 正式便携版整理设计

日期：2026-09-24。关联 [开发计划](015-stable-portable-plan.md)。承接 013 首版与 014 x86 适配；用户已反馈 x86 预览暂未发现使用问题，并要求整理 1.0.0 正式稳定版。

## 范围与版本

- 本次整理可供分发的 1.0.0 x64／x86 自包含 ZIP、双语发布说明、使用帮助、FAQ、许可与 SHA256。不增加功能，不生成或验收安装器，不上传、不自动提交或推送。
- 当前工作区包含已通过自动化的 x86 修复，需纳入两种架构。原 screenkeeper-v1.0.0 标签不含该修复，保持原标签和旧包不动；按用户本次明确指定的版本，归档当前构建源码后以 MinVerVersionOverride=1.0.0 构建。
- 新包使用独立交付目录和构建标识 20260924。EXE 的 SourceRevisionId 使用 snapshot.<源码清单 SHA256>，VERSION 和维护清单记录真实基线提交及未提交改动，不冒充原标签构建。源码 ZIP 与逐文件清单用于精确追溯。
- 常规 MinVer 标签策略不变。此次是用户指定版本的归档构建，不将版本覆盖固化为日常构建默认值。正式包与历史同版本包通过构建标识、源码清单及 ZIP 校验值区分。

## 依赖顺序与验证

1. 整理双语说明与发布范围，冻结应用、测试、解决方案、许可和构建相关配置的源码快照，不复制用户 Data、恢复记录、日志、凭据、bin 或 obj。
2. 从快照构建双架构并运行常规完整测试，检查真实测试进程架构；沿用 014 已完成的受控原生窗口回归，不重复操作真实显示器。
3. 检查实际依赖版本并附齐已有核验许可；压缩后做 CRC、完整解压、逐文件校验、PE 架构与版本检查。
4. 对解压后的程序在业务 Main 前检查自包含运行时、便携标识和界面资源，避免改动用户配置或显示器；不将入口前检查当作完整 UI 验收。
5. 输出两种架构 ZIP、源码归档、双语发布说明、校验文件与维护清单，补齐实际结果并复核 AGENTS.md。

## 验收边界与回退

用户已试用 x64 首版和 x86 预览；新的正式包保持同一功能源码，重新构建版本元数据。Windows 10 原生 32 位系统未实测，不能写为全平台实机验收通过。程序未签名，既有可选原生渲染测试的跨 dispatcher 问题仍按 014 记录保留；不是新引入问题。稳定版名称不代表所有显卡／显示器兼容。

所有产物写入新的 artifacts 子目录，不覆盖运行中的客户端或历史成品。需要回退时先正常退出并完成亮度／原色恢复，再运行保留的旧版本；不删除恢复记录，不用另一台机器的数据替代。此次不更改配置 schema。
