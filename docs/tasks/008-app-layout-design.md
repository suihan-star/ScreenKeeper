日期：2026-09-18。状态：**2026-09-19 用户已确认 v4（含顶部双主题入口），客户端实施与验证完成**。

关联 [执行计划](008-app-layout-plan.md)。基于 [006 设置布局](006-settings-layout-design.md)、[007 健康提醒与色温](007-wellbeing-design.md) 和当前 WPF 实现。本文记录已批准的结构，不替代已确认并运行的行为约束。

## 1. 本轮范围与依据

用户希望重新整理整个软件及两个新增模块，先讨论方案，再决定执行。首轮使用 baoyu-design 的设计分析流程交付结构与交互提案；随后用户要求“先落地设计，看下效果”，设计阶段据此制作 v4 可点击稿；2026-09-19 已确认并实施客户端。验证使用虚构数据，不操作用户真实显示器颜色或配置。

已核对 MainWindow、MonitorConfigurationView、HealthSettingsView、ColorSettingsView、通用设置弹窗和 Calm 主题，观察到：

- 主导航把屏幕对象与健康、色温两个全局模块并列，进入全局页面后仍显示屏幕列表，容易误解设置范围。
- 健康提醒单页同时展示运行倒计时、周期、免打扰、外观与多个预览入口，日常操作被较长表单分散。
- 色温设置同时展开试调、验证、原色重查、原色重建、作息和参与列表；屏幕操作在顶部和底部重复，首次设置与日常调节混在一起。
- 同一页面包含保存后的运行状态、未保存设置和临时预览，需要更明确地区分。

这些是结构问题。继续沿用静绿、A+「叠屏静夜」图标与中英文。2026-09-19 用户追加多主题要求：静绿作为默认，同时可切换最初的雾白绿；信息结构保持一致。

## 2. 总体结构：模块导航，屏幕选择留在模块内

建议采用：

```text
标题栏：ScreenKeeper                  主题  语言   最小化／还原／关闭
┌──────────────┬──────────────────────────────────────────┐
│ 屏幕管理     │ 模块标题 · 设置范围             启用开关 │
│ 健康提醒     │ 当前运行状态与临时操作                   │
│ 色温调节     │ 模块内页签                               │
│              │                                          │
│              │ 当前页设置，随选择显示相关内容           │
│              │                                          │
│ 通用设置     ├──────────────────────────────────────────┤
│              │ 保存范围／未保存状态       放弃     保存 │
└──────────────┴──────────────────────────────────────────┘
```

- 左侧只承担模块切换。屏幕管理默认打开，切换模块保留当前会话中的选屏、页签与草稿。
- 屏幕管理里选屏，健康提醒明确为全局计时；色温为共用作息、选择参与屏幕。
- 不增加独立首页或统计看板。现阶段使用者主要是调整规则、查看状态或临时暂停，模块首页可直接完成。
- 通用设置继续位于左下角，保留轻量弹窗与当前语言／开机启动的生效方式；不让外层保存按钮造成误解。标题栏语言入口保持可见。
- 代价：从其他模块进入某屏设置多一次模块切换；收益：全局与每屏作用范围明确，多屏数量不再挤占全局导航。

## 3. 屏幕管理

模块顶部为紧凑选屏区：编号、名称、主屏标识与未保存标记。两三块屏幕可直接点选；更多屏幕或窄窗口采用有完整名称的下拉列表，避免横向滚动。刷新入口放在此处，有未保存修改时保持现有禁用规则。

选定屏幕后展示管理开关，页签固定为 **屏幕休息 → 隐私保护**，屏幕休息仍为默认第一页。

| 页面 | 首屏重点 | 按需展开 |
| --- | --- | --- |
| 屏幕休息 | 空闲多久、执行方式、相关亮度 | 保持唤醒的条件；需要时可完整查看 |
| 隐私保护 | 启用、等待、保护方式 | 当前方式专属内容、更多设置 |

保留隐私 v3 已确认规则：外观仅在隐私幕方式显示；图片在弹窗集中管理；指定应用只呈现目标、选择和相关选项；默认暂缓放在更多设置。停用保留参数，不恢复“关闭”方式卡片或“推荐”标记。

“应用到其他屏幕”改为更清楚的“复制本屏设置…”，弹窗显示复制范围和目标，完成后提示“已复制，保存后生效”。保留目标管理开关和能力回退。底栏明确保存 **所有屏幕的待保存修改**，不能误标为只保存当前屏幕。

已有立即保护全部屏幕的动作保留在屏幕管理中，明确写“立即保护所有屏幕”；读取已保存规则。隐私页的本屏暂缓与测试仍位于本屏上下文，不把全局保护按钮伪装成本屏操作。

## 4. 健康提醒

顶部为简洁运行状态条：距离下次提醒／当前暂停原因／休息剩余时间，配“现在休息”和“暂停／继续”。操作采用已保存设置，与下方草稿分开。启用开关变化需要保存，待保存状态应就近可见。

设置分成两个页签：

**提醒节奏**

- 连续工作多久提醒、每次休息多久、稍后提醒多久，按这一顺序组织。
- 全屏免打扰直接可见；长时间无输入暂停及其说明放在折叠项中。
- 周期变化在下一周期生效等说明，仅在编辑相关字段时出现，不常驻多段解释。

**提醒外观**

- 先明确“提醒时”和“开始休息后”是两个阶段，再分别选外观。
- 选择雾光／静景后才显示渐显时长、覆盖程度和动态设置；简洁卡片不展示无关调节。覆盖仍支持 100%。
- 图片导入、替换和预览集中在使用图片的阶段；两阶段共用现有图片资源，不暗示已经支持独立图库。
- 增加页面内示意预览，局部样例明确标注。宽窗口与设置并列，窄窗口上下排列。
- 只保留一个明确的“在屏幕上预览”入口，选定需要查看的阶段；真实预览带可退出标记，不推进工作周期，也不把外观草稿自动保存。

新阶段直达预览如需增加命令，只扩展预览入口，不更改真实开始休息的计时语义。自动全屏免打扰与手动外观预览的现有差异继续保留。

## 5. 色温调节

模块说明用一句话表明：**按固定作息调整所选屏幕，与健康提醒的休息倒计时独立。**

### 作息与色温：日常使用

工作开始时间与工作色温放在同一组，休息开始时间与休息色温放在下一组。时间、滑杆和数值不再分散在页面两端。

```text
工作时段     07:00 开始     保持原色 / 自定义
                          更暖 ───────●── 接近中性   5300 K

休息时段     18:00 开始
                          更暖 ───●────── 接近中性   4500 K

逐渐过渡     30 分钟
```

数值是布局示例，不表示正在读取用户配置。原色不等于 6500K；选择原色时，隐藏或停用不生效的工作色温滑杆并显示原色状态。

- 紧凑时间轴位于两组设置旁或下方，同时区分“已生效作息”和正在编辑的值。
- 固定作息作为主要呈现；现有手动模式保留在模式选择中，切换后收起无关时间项，不删除已有功能。
- 试调屏幕放在滑杆附近，只保留一处选择器和一组试调反馈：目标屏幕、当前试调值、恢复倒计时、“按住对比原色”“结束试调”。编辑与实际试调应有不同文案。
- 未选可试调目标时，仍可编辑候选数值，但不能暗示屏幕已变化；展示“设置试调屏幕”入口。
- 15 秒后恢复已保存策略，数值保留在草稿；切换目标、离开模块及保存／放弃仍取消试调。设置页内换页签也结束试调，避免反馈隐藏后继续改色。

### 屏幕与验证：选择设备、处理异常

每屏一行或一张紧凑卡：名称、状态、参与开关、当前可用主操作。例：

| 状态 | 主要呈现与操作 |
| --- | --- |
| 待验证 | “完成 15 秒测试后可用”＋开始设置 |
| 可用 | 参与开关；临时恢复原色／恢复自动 |
| 临时原色 | 恢复截止与恢复自动 |
| 需要处理 | 一句原因＋查看处理步骤 |
| 当前模式不支持 | 明确显示 HDR／复制／远程等实际原因；查看说明 |
| 已断开 | 保留配置与名称；标记不可操作 |

未验证或异常的屏幕仍能选中查看。正常状态不展开验证说明和恢复工具，参与选择与验证是两件事。

“开始设置”或“查看处理步骤”打开一个有上下文的引导窗口：列出目标 → 呈现当前阻塞及下一步 → 用户开始 15 秒测试 → 自动恢复 → 用户观察确认。每一步只突出当前可执行的动作，完整状态与技术详情可以展开。

必须按真实原因分支：

- 已保存策略开启：明确“先关闭并保存色温调节”，提供返回该开关的入口；第一轮不自动代替用户关闭、保存或恢复总策略。
- 恢复冲突：先提供只读重新检查；若仍不同，再展示继续处理的条件。不能用一个万能重试按钮循环同一提示。
- 旧原色需重新建立：进入现有独立流程，明确列出所有受影响屏幕、用户观察确认、归档和重新验证要求，不能合并成无确认的“修复”。
- 模式不支持、存储不可用或当前颜色不稳定：说明真实条件，不承诺点击即可解决。

这轮建议改善入口编排和解释，不放宽验证、恢复日志、外部改色或用户观察的限制。自动暂停并恢复策略属于后续行为变更，需要另行明确设计。

## 6. 统一交互与视觉

- 继续采用现有 Calm 配色。主内容用更清晰的字重和间距区分层级，少用每一行一个卡片的嵌套边框；颜色主要表达选择和状态。
- 页面以“当前状态 → 常用设置 → 按需选项”组织。异常留在对应模块、屏幕或字段旁，阻塞性问题不能只藏在帮助信息中。
- 每个模块最多两层导航：模块 → 页签。不再添加页签内页签；复杂选择使用弹窗。
- 保存条只呈现设置操作。明确“保存屏幕设置／保存健康提醒／保存色温设置”，保留跨模块草稿与各自未保存标记，失败不清除草稿。
- 临时操作与预览放在内容区，标明作用范围和截止，不和保存混排；多个模块不伪装成一次原子保存。
- 启用开关是草稿，运行状态来自保存基线；例如同时显示“当前已关闭”和“开启待保存”，避免切换后虚报正在运行。
- 默认窗口保持约 1000×736，最低仍支持 700×500。导航保留文字，正文滚动、标题栏语言和底部操作保持可达；预览宽屏并列、窄屏叠放，不增加第三条固定侧栏。
- 英文长文案、键盘焦点、缩放下的换行和按钮可达必须在设计稿及 WPF 阶段分别核验，不能只看中文大窗口。
