# 021 · 开源前隐私清理设计

关联计划：[021-open-source-privacy-plan.md](021-open-source-privacy-plan.md)。

## 目标与边界

用户要求将 GitHub 项目开源，并删除项目中的个人私人信息。先完成清理与验证，再开放访问；不把仅删除当前文件当作历史清理。沿用现有 MIT 许可，保留上游作者版权与第三方许可。公开项目地址、产品官网和必要产品标识继续保留。

范围包括当前文件、可公开的 Git 历史与提交／标签身份、图片等资源元数据、Actions 日志及产物。个人本机路径、私人邮箱、内部仓库地址、账号认证过程与账户费用快照等不进入公开项目。技术验收结论可以保留，但应使用中性路径与概括描述。

## 实施路线

1. 只读审计现有 main 与产品标签，区分项目公开身份、上游归属及私人信息；报告仅保存到被忽略的本地 artifacts。
2. 备份当前已提交源码与本地 remote 配置，在独立本地准备目录制作脱敏版本，保留工作区文件和历史原件。
3. 清理文件与必要历史身份，不删除上游许可证，不修改运行逻辑或既有配置格式；同步公开仓库文档与构建门禁。
4. 验证文本与二进制候选、Git 可达对象和提交身份、差异范围、文档链接及工作流。涉及真实历史重写或仓库重建时，提供具体对象和影响，再取得用户对最终操作的确认。
5. 仅在公开范围可核验后执行已确认的远端操作；不要在旧的私人内容仍可访问时切换为公开。

## 风险与回滚

Git 历史重写会改变提交与标签指向，旧克隆不能直接当作新公共历史继续推送。GitHub 旧提交缓存与构建记录并不会仅因修改分支而必然消失；本次经用户确认，采用旧仓库改名并保持私有、原地址新建独立公开仓库的路线，避免公开旧对象。公开仓库只接收已审计的 main 与产品标签，不共享旧仓库的 Git 对象与构建记录。

原始数据仅保存在本地忽略目录或保留的私有仓库，不提交审计报告、替换字典、备份或凭据。未经确认不删除远端仓库，不重写现有远端历史，不删除本地原始备份。

公开后回滚应从已脱敏的公开历史修复；原始备份只用于私有核对，不能重新推送到公开仓库。开源不代表发布新的正式安装包，也不改变已有硬件验收范围。
