# 021 · 开源前隐私清理计划

对应设计：[021-open-source-privacy-design.md](021-open-source-privacy-design.md)。

## 步骤

1. 核对工作区、适用规则、私有仓库状态与可达 Git refs。
2. 分别审计当前文本、二进制素材与元数据、Git 历史及远端构建记录。
3. 本地备份并准备完整脱敏候选，保留上游许可及原始验证事实。
4. 更新公开文档、开发约束与构建配置，执行隐私扫描和最接近变更的验证。
5. 给出清理清单、历史影响和可审阅候选；涉及历史重写／重建时，在完成准备后确认远端执行方式。
6. 执行确认后的发布路线，匿名检查公开内容与构建结果，记录实际状态。

## 远端发布路线待确认

旧构建运行的 API 元数据仍含私人提交身份；只更新分支不能清理此记录和旧提交缓存。准备方案为：将旧仓库改名并保持私有，随后在原公开地址建立仅含已审计历史的新仓库。保留上游原始 197 个提交与 MIT 版权，产品历史的提交／标签对象因脱敏改变；旧包校验值与原始构建证据继续私有留存，不伪造为新历史产物。

本地候选验证完成后再确认具体远端操作。在确认前不重命名现有 GitHub 仓库、不公开、不覆盖其分支／标签，也不删除原始备份。
