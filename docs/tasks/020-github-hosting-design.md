# 020 · GitHub 完整仓库托管与 Mac 构建

关联计划：[020-github-hosting-plan.md](020-github-hosting-plan.md)。

## 用户确认的范围

2026-11-10 用户要求新建 GitHub 仓库，托管完整项目，通过内置浏览器登录。此决定替代 019 中临时最小 Mac 副本的方案：Windows、Mac、测试、设计稿、素材许可和开发文档统一保存在完整项目仓库，保留现有 Git 历史。默认新仓库为私有；不删除 Codeup，不公开源代码，不创建发行版，不启用付费。

上传当前项目相关的已跟踪及未忽略源码；运行数据、日志、恢复记录、密钥、证书、生成包和个人工具状态继续排除。已有未提交的 Windows 修复与文档在本次完整源码托管范围内，先检查差异和验证结果再提交；不为迁移顺带重构代码或重写历史。

## 实施与依赖

先核对 Git 状态、忽略规则、敏感内容和大文件，再完成现有 Windows 构建测试与 Mac 打包脚本检查。用户完成 GitHub 登录后，在其确认账户中新建空私有仓库；验证 Git 认证后推送 `main` 和既有产品标签 `screenkeeper-v1.0.0`，不默认推送上游标签。

初次上传先使用单独 GitHub remote，确认远端提交和私有状态后再将 GitHub 设为 `origin`，原 Codeup 连接保留为 `codeup`，`upstream` 保持不变。文档和根 AGENTS.md 同步真实地址和角色。

Mac workflow 直接 checkout 本次精确提交，构建脚本生成 Mac 输入清单；仅手动触发标准 arm64 `macos-15` runner，20 分钟超时，产物保留 3 天。触发前核对账户可用额度及付费边界，不自动启用付款。持续处理真实编译／测试失败并校验下载的 ZIP／DMG，不能把源码上传完成当作 Mac 可运行包完成。

## 验证与回滚

- 上传前：检查完整差异、现有 Windows 测试、Mac 辅助脚本测试和工作流语法；不运行真实硬件实验。
- 上传后：远端 `main` 提交与本地一致、产品标签一致、仓库私有、预期源文件完整、无运行数据。
- Mac 产物：真实 XCTest、arm64／最低系统／动态库、资源自检、签名状态和归档校验；仍需朋友实机验收显示器行为。
- 失败时保留本地更改、Codeup 和历史产物；未确认上传成功前不替换原 remote。已创建仓库不擅自删除；不强推、移动旧标签或重写历史。
