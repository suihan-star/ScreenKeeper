# 011 · 黑屏恢复与退出遮罩清理

关联 [开发计划](011-blackout-recovery-plan.md)。用户报告 AOC 先黑屏且点击无效、设置窗口无法从最小化打开；随后尝试退出，拔插显示线后恢复且程序退出。

## 已知事实与范围

- 日志最后一次 AOC 遮黑明确未改硬件亮度；约 5 秒后进入退出并停止空闲检测，亮度恢复步骤完成，但没有正常退出完成日志。排查时进程已经不存在，不能取得故障线程现场。不得把退出缺陷当作最初黑屏的唯一原因。
- 代码存在两个需要回归验证的缺口：遮黑在空闲复核之后仍经过异步显示器查询和 UI 排队，恢复可能先于遮罩真正显示；退出时没有先关闭软件遮罩，停止唤醒检测后又可能显示原色恢复模态提示，导致遮罩挡住提示并使主窗口不可交互。
- 修复范围为过期遮黑取消、退出时清理所有自有遮罩及阻止已排队的遮黑／隐私请求、退出恢复提示的可见入口。保持正常输入不解除隐私幕、不修改配置、不放宽色温恢复所有权门禁。

## 实施与验证

将空闲资格传到实际 UI 遮罩创建前复核，取消后不继续降低硬件亮度，并将拒绝结果回传空闲状态机以便重新计时。退出确认后先在 UI 线程停止并关闭软件遮罩、取消隐私操作，再等待硬件恢复，最后才展示可从任务栏找到的恢复提示；终止后的服务拒绝迟到请求。现有恢复日志和硬件恢复超时策略保留。

以模拟排队／延迟查询稳定复现恢复先完成的顺序，测试取消后无残留窗口和硬件调暗；覆盖多屏清理、迟到请求、重复释放和隐私操作取消。核验启动器实际退出顺序。运行相关及完整回归，不启动用户真实规则、不拔插设备、不读取窗口内容。真实初始故障仍需用户观察新版，不能以测试替代实机证据。

## 回滚

仅撤销本轮代码增量，保留原有用户修改及配置／亮度／色温恢复记录；没有持久化迁移。保持当前目录开发，不提交或推送。

## 2026-09-23 后续：关屏后输出未启用的只读排查

用户补充：主机未关机，次日下午两点多打开 AOC 电源后黑屏；拔插 HDMI 未恢复，在 NVIDIA 控制面板重新勾选 AOC 后恢复。调查需区分首次黑屏、拔插后的连接变化与控制面板最终显示的停用状态，不得把最后的状态直接当作最初原因。

范围：核对当前运行版本、显示写入接口、休息／色温配置、应用日志、系统与 PnP 事件、电源策略。所有检查只读，不改显示拓扑、驱动、配置、恢复记录或屏幕颜色，不自动启动硬件测试。对照验证须由用户在方便观察时操作；证据不足时保留不确定性，不为解释现场擅自修改功能。结论与查询结果见 [现场排查记录](011-aoc-display-diagnosis-2026-09-23.md)。
