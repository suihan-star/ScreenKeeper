# 007 · 健康提醒与色温调节任务设计

日期：2026-09-17。关联 [竞品研究](007-wellbeing-research.md) 与 [开发计划](007-wellbeing-plan.md)。

## 2026-09-18 修复：旧原色包含外部调色时的重新建立流程

用户退出 f.lux 后仍无法通过原色重查。只读检测确认 f.lux 已退出，两屏当前 Gamma 全部等于线性曲线；旧记录的绿色／蓝色已被压低。因此“回到旧原色”不足以处理在外部调色期间采集的旧基线，不能继续要求用户反复退出软件。

- 增加独立的“重新建立原色”入口，用于已关闭并保存色温策略、无预览／验证、恢复日志可读的状态。它与只读重查分开，不会自动采用未知颜色。
- 弹窗先只读检查所有待处理恢复记录对应的当前屏幕，列出屏幕名称。身份、拓扑、模式及 SDR 可读条件须匹配，多次采样须稳定；离线、模式变化或读取失败则保留记录并说明原因。显示本次会处理哪些屏幕，用户明确确认其他调色功能已关闭、这些屏幕当前画面正常后才能继续。
- 确认时重新检查快照与颜色。先通过耐久写入创建唯一的 `color-temperature-archive-*.json` 归档，保存原日志、当前用户确认的颜色及时间；再撤销这些屏幕旧验证资格，最后原子移出活动恢复记录。任一步失败保留活动阻塞，不能以归档成功代表已完成；归档不参与自动恢复。失败重试可以产生多个独立归档，不覆盖或删除先前文件。
- 全流程不写显示器、不修改色温启用状态或工作／休息草稿，不授予验证资格；清理后必须重新完成每屏 15 秒测试和人工观察确认。此处“建立原色”表示确认下一轮验证的起点，不把线性 Gamma 等同于物理校色或擅自强写 6500K。
- 活动恢复日志 schema 1 增加可选 ValidationRequiredScreens，随记录移出同次耐久保存，防止验证文件从旧备份恢复后重新取得旧资格；旧日志默认空列表。新 15 秒试验及人工确认成功后，必须耐久移除该屏标记，才能正式参与。列表参与深复制及存储校验，归档只保留证据，不被恢复加载器读取。
- 回滚时关闭并保存色温、确认正常退出，保留归档和恢复文件；旧版本忽略归档，资格已撤销的屏幕仍不可自动接管。归档不能被旧备份自动复活为活动恢复记录。

验证：归档刷盘及深复制、拒绝资格撤销失败／日志写入失败／采样变化／模式变化／会话锁定／设置启用／过期确认，处理范围一致、全流程零硬件写入、重启资格仍撤销、中英文界面及最小窗口。开发工具不代替用户执行真实重建与调暖。

## 2026-09-18 修复：验证与试调入口的阻塞反馈

只读核对发现 DELL 具备 SDR 扩展和 Gamma 可读条件，但未保存验证资格；已保存的总开关仍开启，两屏恢复日志均有冲突标记，当前读回也不等于原基线。不能据此断言 DELL 不支持调色，或删除记录强行放行。

- 试调下拉允许选择所有屏幕，在名称旁标注可试调／待验证／需处理状态；选择只查看状态，不自动写硬件。所选屏幕就近展示原因、验证与恢复入口，实际拖动继续受资格与冲突门禁约束。
- 验证弹窗在开始前展示已保存策略开启、恢复冲突、记录不可用及显示模式限制等具体原因，不能仅靠禁用按钮表达。准备观察复选框未勾选时明确提示下一步。
- 新增用户主动“重新检查原色”：串行且只读设备，仅在精确物理作用域一致、当前读回已等于记录原色时耐久清除恢复阻塞；仍有不同则保留记录，提示关闭其他调色工具／恢复原色后重试。不强写旧基线、不接纳当前未知颜色为新基线、不自动改写用户已安装配置。
- 验证前恢复门禁沿用既有全局保护；已保存策略开启时明确要求关闭并保存。回滚仅撤回入口和只读重查逻辑，持久化格式不变。

验证覆盖可选但不可试调状态、待验证／暂停／冲突提示、验证前置条件、精确原色解除与不匹配／模式变化／持久化失败继续保留日志，并核验中英文窄窗口。真实调暖由用户在客户端明确开始并观察。

## 2026-09-18 已确认增量：固定作息双目标与滑杆试调

用户确认采用工作／休息两个固定时段，各自设置色温，不与健康提醒倒计时联动。此节替代首版仅有一个暖色目标的约定。

- 工作与休息分别提供 3500–6500K 滑杆（左暖右中性，100K 步进）和整数输入；工作时段另可保持接管前原色。schema 1 新增可选 DayKelvin（默认 5300）和 DayUsesOriginal（默认 true）；旧 NightKelvin 继续代表休息目标，不迁移或改变旧配置的实际行为。
- 固定作息复用 MorningStart／EveningStart 与过渡时间，改为工作开始／休息开始。在两个指定目标间平滑过渡，工作保持原色时仍恢复真实基线；原色不等于 6500K。手动模式沿用休息目标。
- 用户先明确选择已验证的试调屏幕，再拖动或输入数值实时试调；值只进入草稿，不自动启用、勾选屏幕或保存。其他屏幕按原有策略运行。快速输入合并为最新值，设备访问继续串行，取消必须使未执行请求失效。
- 停止调整约 15 秒后恢复当时已保存的策略，保留草稿数值。切换试调目标、离开页面、关闭／最小化、保存／放弃、锁屏及退出撤销试调。预览计时使用单调时间，不能因系统时钟修改无限延长。
- 活跃试调提供“按住对比原色”，鼠标或空格／回车按下显示接管前基线，松开回到刚才的试调值；丢失捕获／焦点须结束按住状态，页面退出优先取消，不允许晚到的释放事件重新调色。
- 原色对比期间仍保留恢复日志与接管所有权；如果其他工具改变颜色，松开时不得将外部结果接纳为新基线或覆盖它。UI 合并快速编辑并限制在途请求，服务使用独立预览版本号，取消旧试调不能丢弃已排队的正式保存策略。
- 资格、拓扑、外部冲突、耐久恢复日志和未验证设备禁用规则保持不变。试调采用受限频率即时目标，正式保存及日程仍按既有平滑恢复流程运行；不在开发验证中自动操作用户真实屏幕。

验证包括旧文件兼容、两个作息边界及反向作息、最新值合并、取消竞争、原色对比与恢复、失效设备、写入失败和中英文最小窗口。回滚前关闭色温并确认恢复；旧版忽略新增字段并回到白天原色，保留配置和恢复日志。

## 2026-09-18 已确认增量：渐显提醒与设备验证入口

用户确认直接实施静景渐显提醒和静夜微动休息画面，并要求解决色温始终未验证的问题。本节替代下文第一版的固定小卡片及“预览服从全屏免打扰”约定，其余计时、隐私优先、独立存储与恢复规则保留。

- 自动提醒默认在前台可用屏幕渐显远山静景，8 秒达到 30% 覆盖，操作卡保持清晰；另可选雾光边缘或简洁卡片。装饰窗口独立且输入穿透，提醒不抢焦点、不截图工作内容。
- 主动开始休息后才显示完整静夜画面和倒计时；支持图片画面、静态及轻微动态。普通输入不结束休息，操作区闲置淡出，移动鼠标重新显示。隐私、遮黑、锁屏或宿主失效时立即收起，不播放退出动画。
- 渐显 2–20 秒、覆盖 10–100%、动态开关及强度、自定义一张图片均可配置。图片采用产品私有不可变副本，独立 HealthImages 目录；损坏/缺图回退内置矢量静景，不影响原有隐私图片。
- 2026-09-18 雾光细化：采用更深的森林绿底色与多层错速流动的柔和薄雾，动态强度控制移动幅度，关闭动态或系统减少动画时保持静态。覆盖 100% 时完全盖住背景，默认仍为 30%；所有覆盖设置继续使用现有草稿、预览和保存流程。提醒操作卡保持清晰，提醒输入穿透及隐私优先规则不变。
- 手动预览使用外观草稿，允许普通全屏应用和手动暂停期间预览；仍检查会话及屏幕保护，不推进/重置真实周期。预览可进入示例休息画面，清晰标识为预览。
- 色温未验证的根因是生产注册表固定返回 false。改为每屏受控验证入口：明确目标和其他调色工具条件，用户点击开始后保存可恢复基线，5000K 调暖 15 秒，自动恢复并复核，然后用户确认目标变化、其他屏幕不变、恢复正常。没有人工确认不得取得资格。
- 验证与生产调色共用串行控制和恢复日志；取消、窗口关闭及退出须恢复。试验许可只在内存中短期存在，仅用于所选 SDR 扩展屏；恢复已持久化、作用域及所有权匹配的基线不依赖正式资格，以支持验证被中断后的恢复。
- 资格独立保存于 color-temperature-validation.json，绑定物理身份、拓扑和模式；切换 HDR/复制/不同设备组合后重新验证。资格不代表专业校色认证，不自动勾选参与或保存全局启用。未知配置版本、未恢复日志、外部改色和写入失败继续阻止接管。
- 本轮开发不在无人观察时触发真实改色，不从旧单次 DELL 实测直接授予生产资格；交付可在客户端完成的验证流程。

验证：状态机/草稿/持久化兼容测试，受控色温成功、取消、恢复失败、外部冲突、拓扑变化及确认资格测试，WPF 中英文/最小窗口与静态动效帧核验。真实跨屏改色仍需用户在客户端观察确认。回滚：先关闭色温并恢复原色，保留恢复及资格文件；新增外观字段为 schema 1 可选字段，旧版忽略。

状态：2026-09-17 用户通过研究任务授权进入开发，沿用当前未提交产品基线。**健康采用轻提醒，主动开始后倒计时；色温按固定作息自动变化。**首版采用可编辑默认值：工作 50 分钟、休息 300 秒、稍后 5 分钟；18:00 转暖、07:00 恢复、30 分钟过渡、候选 4500K。这些是产品默认值，不是医学阈值。色温真实接管仍须通过 P1 可逆控制验证，未验证设备不可启用。

## 1. 目标与边界

目标用户是长期使用 Windows 单屏或多屏办公、希望减少手动配置并保留工作控制权的人。用户已补充实际环境：两块屏幕，未开启 HDR，程序员，偶尔做页面设计。因此优先验收双屏 SDR、正常编程不被打断、检查页面颜色时可将本屏临时恢复原色。屏幕型号、显卡、接口与扩展／复制模式尚未核验，不据此假定独立调色必然可用。

- 健康提醒解决“投入工作而忘记适时离屏／活动”的问题；一人一套计时，不因更换操作屏幕而重置。
- 色温调节解决“每天反复手动调暖”和“不同用途屏幕需要选择性参与”的问题。
- 两模块可以单独启用，不要求启用现有屏幕休息或隐私功能。
- 本期不做强制锁定、医疗监测、摄像头注视检测、健康评分、云同步、员工监管或专业显示器校准。
- 色温不自动控制亮度；休息提示不替代隐私幕，不最小化应用、不强制锁屏或改动用户窗口。

## 2. 产品结构与入口

保留已有左侧显示器列表，点击显示器仍进入“屏幕休息／隐私保护”。左侧增加独立模块入口“健康提醒”“色温调节”，通用设置保留。选中全局模块时不显示当前屏幕管理开关。

```text
左侧导航                         右侧内容
显示器                           点选显示器：屏幕休息 | 隐私保护
  1 主屏                         健康提醒：当前状态、周期、提醒方式、免打扰
  2 副屏                         色温调节：时间表、过渡预览、参与屏幕及状态
健康提醒
色温调节                         固定底栏：当前模块的放弃／保存
通用设置                         语言入口固定可见
```

收益是模块作用范围明确，代价是全局模块切换和保存范围需要调整。现有每屏管理开关仍只控制原有屏幕休息／隐私，不悄悄扩大含义。

- 色温页面使用统一作息表及屏幕列表，首版每屏只提供参与、暂停和状态，不给每屏独立时间表。
- 健康页面提供“预览提醒”，仅短暂展示带“预览”标记的示例卡片，不推进真实周期、不记录完成，关闭后原状态保持；预览仍服从隐私／全屏免打扰。
- 700×500 下正文滚动，导航、语言和底栏可见；屏幕条目纵向排列，不再横向增加多个页签。
- 模块切换保留各自草稿和脏标记；显示器拓扑更新仍按 HardwareId 合并草稿。
- 底栏分别标为“保存所有屏幕设置”“保存健康提醒”“保存色温设置”，保存只影响当前模块，其他模块显示未保存标记。退出时明确列出未保存模块；关闭窗口到托盘不丢草稿。
- 托盘增加“现在休息”“暂停健康提醒 1 小时”“恢复健康提醒”“色温恢复原色 1 小时／恢复自动”。均操作保存基线与运行状态，不保存界面草稿。

## 3. 健康提醒

### 3.1 典型场景与建议默认值

用户连续办公一段时间，当前屏幕边缘渐显“该休息一下了”；可开始、稍后或跳过。开始后显示休息倒计时，结束后重新进入工作周期。副屏正处于隐私保护时，不在该屏展示提示。

以下数值都是**本产品建议，非竞品默认值或医学处方**：

| 设置 | 首版建议 | 校验／说明 |
| --- | --- | --- |
| 总开关 | 默认关闭，首次自行启用 | 老用户升级不被突然打扰 |
| 工作周期 | 50 分钟 | 正整数 5–180 分钟 |
| 休息倒计时 | 5 分钟 | 正整数 20–900 秒；UI 可秒／分钟输入 |
| 稍后提醒 | 5 分钟 | 正整数 1–30 分钟 |
| 提示 | 约 1 秒渐显、停留 20 秒、默认无声音 | 尊重系统减少动画设置；不闪烁 |
| 全屏免打扰 | 开启 | 保守判断，另有手动暂停兜底 |
| 长时间无输入 | 5 分钟后暂停工作累计 | 高级项可关闭；明确阅读／观影可能被误判 |

首版只有一套可编辑节律，不同时叠加短休息与长休息。以后可新增“短暂远眺”等预设；不把更多提醒种类塞入最小版本。

### 3.2 计时语义

- 使用单调时间源累计当前已解锁、未休眠会话的工作时间；它是工作周期估计，不统计真实劳动、注视或身体活动。
- 不因鼠标在屏幕间移动而增加第二个计时，不因屏幕插拔或隐私服务重启而重置。
- 默认长时间无输入达到 5 分钟后，暂停累计；此前已累计部分保留，返回输入后继续。只显示“因无输入暂停”，不自动记录已休息、不自动清零。用户可关闭此规则以适应阅读。
- 锁屏／系统睡眠立即暂停；解锁／恢复后保留未完成周期，30 秒稳定期内不弹提示，不补发离开期间的提醒。无输入期间、手动暂停期间均不积压多条提醒。
- 定时轮询间隔建议 1 秒；异常大时间跳变／事件缺失时转为暂停并重新取会话状态，不把整段系统睡眠算成工作。
- 进程重启从新的工作周期开始，不把离线时间算工作；配置和显式“暂停到”的截止时间保留，工作累计和休息历史首版不持久化。

### 3.3 状态与操作

| 状态／事件 | 行为与下一状态 |
| --- | --- |
| 关闭 → 保存启用 | 从完整工作周期开始计时；界面显示预计提醒时间 |
| 工作中 → 周期到期 | 若允许展示则显示一张提醒；被免打扰阻止则只有一条待提醒 |
| 到期时持续输入 | 不抢焦点；普通窗口下最多等待 60 秒较安静时机，之后仍以非激活提示呈现；全屏／锁屏优先阻止展示 |
| 提醒 → 开始休息 | 关闭提醒，开始一个倒计时；原累计保留到完成或提前结束 |
| 提醒 → 稍后 | 从点击时起，累计设定的有效使用时长后再提醒；不清零原工作周期 |
| 提醒 → 跳过本次 | 本周期结束，重新开始完整工作周期；不计为休息完成 |
| 提醒超时／关闭按钮／Esc | 等同稍后，既不强制开始也不记为完成 |
| 倒计时结束 | 记录会话内“计时已结束”，清零工作累计；不自动唤亮或解除隐私 |
| 倒计时 → 提前结束 | 不记为完成；相当于稍后提醒，避免立即反复弹出 |
| 任意状态 → 手动暂停 | 关闭健康窗口，暂停计时；恢复后继续原工作累计，已开始的休息计时取消 |
| 修改周期并保存 | 已运行的休息／稍后截止不改变；新参数在下一周期使用，页面说明何时生效 |
| 保存关闭 | 立即取消健康窗口和待提醒；不影响其他模块 |

休息计时中正常鼠标／键盘输入不会误关闭窗口，只有明确的提前结束按钮或卡片内 Esc 可以退出。**Esc 仅在用户主动聚焦健康卡片时生效，不注册全局 Esc，也不拦截 IDE／浏览器按键**；未聚焦时通过按钮／托盘操作。即使用户继续工作，倒计时结束也只说明时间经过，不宣称他完成了休息。休息开始后的锁屏／睡眠时间可计入倒计时，恢复后最多展示一次非打扰的计时结束状态，不补开覆盖窗口。

### 3.4 提示、免打扰与多屏规则

- 默认只在前台应用所属且可用的屏幕显示一张非激活提示卡，边缘有轻微渐显背景；透明装饰区域输入穿透，按钮区域可点击，不能整个提示都穿透。找不到合适屏幕就延后，不去唤亮其他屏幕。
- 点击开始后在该屏显示非全屏倒计时卡，可折叠到托盘；倒计时所有屏共享。不自动全屏遮挡，不复用 PrivacyCurtainHost。
- 当前用户前台全屏应用存在时自动延后；判断采用窗口几何／显示区域，不读标题和内容，不根据应用名声称“正在会议”。非全屏会议可用手动暂停。
- 全屏退出且会话稳定 30 秒后只展示一个待提醒；手动暂停比到期提醒优先。连续免打扰没有强制打断上限，状态页明确显示“因全屏延后”。
- 健康窗口显示期间隐私／遮黑触发，立即收起相关健康窗口，保留计时；全屏或屏幕断连也收起，倒计时继续在托盘，不自动迁移覆盖到其他屏。
- 健康窗口须从现有“回到桌面／指定应用”窗口枚举中排除，并在隐私动作开始前收起；避免本产品窗口被当作用户应用处理。
- 全屏识别失败时保守延后并显示简短原因；输入时间读取失败时暂停累计，低频提示，可重试，不虚构准确计时。

## 4. 色温调节

### 4.1 典型场景与建议默认值

用户白天保持原色，18:00 开始逐渐转暖；修图时让主屏暂时恢复原色，副屏继续按日程运行。次日恢复阶段回到接管前原色。下列方案只有在实际后端支持独立控制时成立，否则禁用该设备的独立入口并解释原因。

| 设置 | 首版建议 | 边界 |
| --- | --- | --- |
| 总开关 | 默认关闭 | 不自动替代用户正在使用的 f.lux／夜间模式 |
| 模式 | 固定时间自动／手动暖色 | 不需要联网、位置或天气 |
| 白天 | 原色 | 原色是接管前基线，不固定设为 6500K |
| 夜间 | 约 4500K 的暖色目标 | 候选可调范围 3500–6500K；软件估算值不代表仪器实测白点，最终随后端验证修订 |
| 转暖开始 | 18:00 | 本地时间，可按夜班调整 |
| 恢复开始 | 07:00 | 跨午夜，不能与转暖开始相同 |
| 过渡 | 30 分钟 | 候选 0–120 分钟；必须短于两个相邻时点的间隔，避免重叠 |
| 参与屏幕 | 首次全部未勾选，用户选择已验证可控屏 | 新接入屏幕默认不参与；老设备恢复已保存偏好 |
| 临时暂停 | 本屏或全部，1 小时／直到下一次恢复开始 | 页面和托盘显示明确截止时间，可立即恢复自动 |

手动暖色使用独立模式及同一暖色强度；暂停优先于模式。用户在晚间临时改滑块只编辑草稿，正式应用须保存；可使用有时限的预览。

### 4.2 日程与状态

- 18:00–18:30 从白天基线插值到暖色；18:30 至翌日 07:00 保持；07:00–07:30 逐渐恢复基线，其余保持原色。页面显示今日时间轴、当前目标、下一次变化和各屏实际状态。
- 用当地日期／时区计算目标，用单调时间推进短暂过渡。时钟／时区／夏令时改变后重算当前目标；用短过渡靠近新目标，不补播错过时段、不重复排队执行。
- 自动模式下日程修改保存后重算目标；已有暂停截止不改。首次接管或睡眠恢复时从可验证当前状态过渡到当前目标，不瞬间回放一整晚的变化。
- 显示状态至少区分：未启用、正在检测、原色、渐变中、暖色已应用、暂停至某时、离线、不支持、冲突已暂停、应用失败、恢复待处理。保存成功不等于设备应用成功。
- 预览默认 15 秒，到期／取消／关闭页面／保存失败均撤销预览并返回当前已保存策略；不拿预览值当新基线。显示屏范围必须明确。能力未确认时只预览时间轴，不调用设备。
- 不支持的设备保留偏好草稿但不能启用；首次启用校验必须明确逐屏失败原因。多屏运行时一屏失败不反复重试其他成功屏，页面给出逐屏状态。

### 4.3 后端选择：先验证，不先承诺

| 路线 | 适合验证的用途 | 发布约束 |
| --- | --- | --- |
| Gamma ramp | SDR 上软件渐变的候选 | 微软不推荐且存在静默失败、共享作用域、校准冲突；必须限制兼容范围，不以返回值证明生效 |
| DDC 色温／RGB gain | 已验证外接显示器的物理控制 | 色温可能只有离散档位；必须检查连带 OSD／gain／drive 变化和可恢复性；不能伪装成连续平滑曲线 |
| Windows 夜间模式入口 | 不支持环境的可选系统设置入口 | 不视为我们已实现自动调度；本轮没有证据可承诺公开 API 接管其设置 |

首版预研目标为**可独立寻址的 SDR 扩展屏**。HDR、自动颜色管理、复制屏、远程桌面、复杂校色环境都需单独结论；未验证时禁用实际接管。若只有 DDC 离散档位可靠，应明确提供“定时档位切换”，并重新评审是否满足用户预期，而非宣称无级渐变。

只有以下条件全部满足才能选择正式后端：目标作用域可识别；基线可读取并持久化；写入效果可验证；暂停和正常退出可恢复；外部调色时能停止竞争；失败不会影响未选择屏幕。如果做不到，保留设计并报告阻塞，健康模块可独立交付。

### 4.4 原色、接管和异常恢复

1. 每个控制范围单独检测，保存稳定硬件身份、当前拓扑／模式、后端种类、接管前基线、最后写入值和会话标识。不能只用会变化的 DISPLAY1 名称匹配。
2. 恢复记录可靠写盘成功后才首次改色。读取基线或写恢复记录失败就不接管，页面报告原因；不影响原有亮度记录。
3. 暂停／关闭／退出时，仅在目标身份、显示模式和当前状态仍符合本次接管范围时恢复。若发现外部修改，停止控制并报告冲突，不用旧基线覆盖别人。
4. Gamma 读回只能作为部分证据，不保证实际像素管线正确；预研须人工检查画面和未选屏的独立性。首次启用不假设能完全自动识别所有调色软件，界面提示用户只启用一个控制方。
5. 同一控制范围串行、可取消、合并过期目标；原生 I/O 放后台，输入回调和 UI 线程不执行硬件操作。不每秒写恢复日志，不反复争抢被外部覆盖的状态。
6. 屏幕断连取消待执行写入，保留偏好和待恢复记录。重连重新识别、检测能力／控制范围，无法确认旧记录适用时停止自动接管并提供恢复提示，不盲写。
7. 系统睡眠／锁屏暂停新增写入，恢复后重新检测并按当前时间继续；不得唤亮屏幕或关闭隐私。HDR／色彩模式切换时使旧能力和基线失效；切换后不使用已失效的旧记录写回新管线。
8. 正常退出等待恢复；恢复失败保留记录并告知用户。强制结束／崩溃不能承诺即时恢复；下次启动先处理恢复记录，不能把上次残留暖色当正常新基线。模式／外部状态不明时提供人工恢复流程，禁止恢复出厂设置。

## 5. 模块之间的规则

| 同时发生的情况 | 必须出现的行为 |
| --- | --- |
| 隐私触发与健康提示 | 隐私优先；收起提示，不解除隐私；倒计时可继续 |
| 屏幕遮黑／调暗与健康到期 | 不唤亮，不在休息屏显示提示；可用屏再决定是否提示 |
| 色温暂停与隐私已开启 | 只调整色温控制，不关闭幕布、不改变暂缓 |
| 色温工作与亮度恢复 | 各自独立基线；若使用 DDC，设备访问需统一排队但不混合状态语义 |
| 用户取消健康提示 | 不把取消动作映射为解除隐私；按钮抬起完成后再关闭，避免穿透误点击 |
| 拓扑变更 | 健康只有一个周期；色温取消旧映射写入，重新探测；屏幕设置草稿保留 |
| 所有屏幕保护／睡眠 | 健康不弹出；色温不触发唤醒；页面下次打开可见当前状态 |

## 6. 技术边界与存储建议

以下命名为拟议实现，不表示项目已存在：

- `Features/HealthReminder`：纯计时状态机、`IUserActivitySnapshot`、会话／电源事件适配、提醒协调；全局计时独立于 MonitorIdleDetectionService 和隐私服务生命周期。
- `Features/ColorTemperature`：纯时间表计算、能力模型、`IColorTemperatureBackend`、逐控制范围协调、基线／恢复存储。
- `Native/`：封装经过预研选定的显示 API、会话及电源通知；UI 不直接调用这些接口。
- `UI/`：健康／色温 ViewModel、视图和独立健康提示宿主，复用 Calm.xaml 与中英文机制；不修改线程文化。
- `Storage/`：复用 IAppDataFileStore；新增功能各自维护版本与校验，保留现有 `settings.json` schema 1 和 `ui-preferences.json` 行为。

建议在产品数据根新增独立 `health-reminder.json` 和 `color-temperature.json`，各有自身 schema 1；后者包含共享作息与 HardwareId → 参与设置，单模块单文档原子保存。临时暂停截止及恢复记录置于独立运行状态文件，不混入保存基线。没有跨文件“保存全部成功”的承诺；运行状态写失败时不能声称暂停已跨重启持久化。

配置缺失默认关闭；损坏先尝试备份，失败时关闭相应模块并提示。未知 schema 不覆盖原文件，保持禁用直至明确迁移／恢复；旧版本不会读新文件，降级前先停用并恢复色温。离线屏配置不删除；相同硬件身份冲突时不自动继承控制。

每次保存先完整校验并深复制，写成功才推进基线和通知服务；失败保持草稿和旧运行策略。写盘成功但设备应用失败时，显示“设置已保存，屏幕 X 未生效”，而非整体绿色成功。

仅记录错误分类、必要硬件标识和状态变化，不记录按键、标题、屏幕内容、浏览记录、健康推断或位置。首版无新增网络服务、驱动安装或管理员注册表修改；第三方依赖只有预研证明必要后再评审许可与体积。
