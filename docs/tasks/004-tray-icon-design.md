# 004 · 托盘图标设计

客户端当前状态：第六轮 A「雾绿轮廓」已确认并完成代码接入与构建。任务栏和托盘统一按系统主题使用浅绿／深绿；轮廓与配色沿用第五轮，第四轮提亮方案不启用。实际 Explorer 主题切换和固定图标状态仍待实机确认。

- 关联计划：[004-tray-icon-plan.md](004-tray-icon-plan.md)。
- 请求：使用 baoyu-design 设计 ScreenKeeper 状态栏小图标。此处按 Windows 通知区域（系统托盘）理解。
- 继承已确认的静绿风格，设计输出到 designs/screenkeeper-calm。用户现已确认 A+ 实施，客户端图标同步接入。
- 三个方向：A 叠屏（推荐，重叠屏幕表达多屏）、B 静夜（月牙表达休息）、C 并屏（并排屏幕表达统一管理）。
- SVG 使用 16×16 网格，简洁实心轮廓；深色背景使用 #B4D6A1，浅色背景使用 #315F43。透明背景，无文字、光晕或持续动画。
- 图标是产品标识，不表示保护已开启、当前亮度或真实运行状态。
- HTML 外围以 16/20/24/32 CSS 像素展示真实大小，画布内展示放大方向对比。浏览器缩放和系统 DPI 会影响最终设备像素。
- 独立深浅版本分别服务深浅任务栏；实施后托盘跟随 Windows 系统主题选择，客户端自身保持静绿主题。
- 没有新增产品运行时依赖。React 复用设计目录本地版本，画布来自 baoyu-design starter。


## 第二轮：A 叠屏＋B 月牙
用户选择 A 轮廓并要求加入 B 月牙，新增 A+「叠屏静夜」。保留 A 的路径，在前屏留白内放置同色月牙；新增 stackmoon-dark.svg / stackmoon-light.svg。评审默认 A+，保留 A、B 作对照，C 源文件继续保留。16 px 内月牙细节有限，需在选定后的原生 ICO 阶段继续验证。

## 已确认实施范围
- 将 A+ SVG 保存至应用 Assets，生成 16/20/24/32/40/48/64/128/256 像素 ICO；程序与安装器使用深绿图标，静绿标题栏使用浅绿图标。
- 托盘读取 Windows SystemUsesLightTheme，浅色任务栏使用深绿，深色任务栏使用浅绿；响应系统偏好通知，在 WPF UI 线程更换，并释放旧 Icon 和事件订阅。读取失败默认浅绿。
- 使用 Windows WPF 离线渲染生成资源，无新增包；图标标识不与显示器保护状态绑定。
- 不更改显示器配置或启用真实硬件行为。保留已有变更，不提交或推送。

## 第四轮：提高深色任务栏可见度
用户反馈托盘图标过暗。当前用户 Windows SystemUsesLightTheme=0，确认为深色系统主题；将 icon-dark.svg 及已确认 A+ 预览的前景色从 #B4D6A1 提升为接近白色的 #F0F7EB，保留轮廓、月牙、尺寸和透明背景。浅色任务栏继续用深绿 #315F43，避免在浅底上盲目提高亮度而降低对比。共用此资源的客户端标题栏同步提亮。重新生成 ICO，验证图标资源并更新便携包；不自动终止或覆盖正在运行的应用。

## 第五轮：撤销提亮，扩大图标占比（当前方案）
用户取消第四轮提亮，恢复深色任务栏的 #B4D6A1，浅色任务栏仍为 #315F43。保持 16×16 画布和叠屏/月牙特征，几何边界从 x=0..15、y=2..15 扩大为 x=0..16、y=0..16；前屏由 12×8 增至 13×10，月牙缩放由 .6 增至 .8，底座加厚至 2 像素。扩大可见轮廓占比，不改变 Windows 管理的托盘槽位。生成脚本按数值读取月牙变换，仍只支持 translate 后 scale 的路径变换。同步两套 SVG/ICO 及设计预览。

## 第六轮：任务栏可见度设计（2026-09-23，已确认 A）

- 用户提供的截图是 Windows 主任务栏。修复前 MainWindow.xaml 的 Window.Icon 固定引用深绿 icon.ico；TrayIconService 已按系统主题选择通知区域图标。两处不同，不能把本次截图归因为浅绿托盘资源本身过暗。
- 保留 A+ 叠屏与月牙身份，先提供独立 `taskbar-icon-v6.html`，不覆盖已确认旧稿或生成生产 ICO。
- A「雾绿轮廓」：原几何不变，深底用现有 #B4D6A1，浅底用 #315F43，作为最小调整方案。
- B「雾绿底牌」：浅绿实色圆角底牌与深绿叠屏，增加可见色块面积，建议用于主任务栏／应用图标；通知区域继续采用 A 的透明轮廓。此处是建议，不改变运行时资源职责。
- C「双层实色」：保留叠屏结构，将前屏填实、月牙反色；深浅任务栏使用对应配色，用于比较小尺寸辨识度。
- 对比页包含用户原截图及 HTML 图层模拟替换、16/20/24/32 CSS 像素深浅背景、放大画布和可切换候选。原截图原样复制，不修改像素；模拟不代表原生 Windows 的最终渲染。
- 无需重新扩大图标画布或加入发光、文字、动画。不修改显示器设置，不更换正在运行的应用或系统图标缓存。
- 最终选择：任务栏和托盘均使用 A；B／C 仅作为历史对照，不再推荐 B。
- 实施：复用现有两套 SVG／ICO，抽出共用的系统任务栏主题读取；MainWindow 在显示前设置 Window.Icon，接收系统偏好变化后在 UI dispatcher 更新，真正关闭时移除订阅并拒绝迟到更新。隐藏到托盘时保留订阅。
- 不绑定客户端 ThemeIcon，避免应用主题与 Windows 系统主题混用；程序文件／安装器仍使用静态深绿 ICO。未运行时固定快捷方式由 Windows 管理，不能宣称 Window.Icon 能动态改变它；不修改用户快捷方式或图标缓存。
- 官方依据：[WPF Window.Icon](https://learn.microsoft.com/en-us/dotnet/api/system.windows.window.icon?view=windowsdesktop-8.0) 用于窗口任务栏按钮及 Alt+Tab；最终 Explorer 缓存、固定分组和 DPI 效果仍须实机确认。
