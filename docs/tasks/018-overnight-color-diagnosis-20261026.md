# 2026-10-26 · 锁屏关显示器后色温反复要求处理

关联 [018 设计](018-crash-color-investigation-design.md)与[计划](018-crash-color-investigation-plan.md)。现场确认恢复使用后提示“查看处理步骤”或要求处理原色恢复；公开记录将真实用户的会话日期和时刻改为相对顺序。

## 结论与范围

现有代码存在明确的恢复处理缺口：锁屏暂停期间保留上次暖色及恢复记录；解锁时只接受当前颜色等于上次写入值，即使颜色精确回到已记录原色，也会持久化为冲突。这能解释用户感受到的“验证又失效”，但不能由现有证据确定某次重置颜色的具体进程或驱动事件。

另外，验证绑定的精确作用域包括系统临时显示编号、全部连接屏幕和模式指纹。关屏重连后即使物理屏幕不变，也可能暂时不匹配；这与恢复冲突是两种不同原因，不能全部当作验证文件丢失。

本轮仅只读调查、纯内存模拟与记录结果，不修改生产代码、运行程序、用户 Data、注册表或显示器颜色，不重新打包。

## 现场证据

- 正式目录：早先的关屏周期中，活动屏幕先从两块变成一块，恢复两块后原色记录写入冲突。验证文件仍保留先前的 AOC 观察确认，`ValidationRequiredScreens` 为空。
- 当前测试目录：两个不同的关屏周期均记录活动屏幕变为一块，并在后续恢复为两块。这证明软件观测到连接组合变化，不能据此推断两块显示器的确切电源开关时刻。
- 较早一次原色重建归档：AOC 旧记录为冲突，新观察与旧原色全部 **768 个采样值相同**；物理屏幕身份相同，拓扑与模式指纹不同。
- 本次原色重建归档：AOC 旧记录仍为冲突，但新观察与旧原色全部 **768 个采样值相同**，且 **完整作用域也相同**。新观察与上次写入暖色不同。这是“回到已知原色却仍被冲突阻塞”的直接现场证据；归档不是冲突发生瞬间的快照，不能据它确定当时的实际写入者。
- 本次 AOC 验证确认后，活动恢复记录 `Conflicted=false`、无待写值、无强制重验证标记；说明本轮重建与验证已完成。本次调查不再要求重复操作。
- 只读 ColorProbe 查询当前两屏均为 SDR、扩展模式、Gamma 可读；工具自身不加载产品验证库，其默认 Unverified 输出不能用来判断用户资格丢失。当前 AOC 作用域与本次新验证记录一致；DELL 的旧资格仍属于历史作用域，且保存策略关闭。
- 当前未观察到 f.lux 进程；这不能排除历史其他进程或系统事件改色。没有证据认定本次为用户误操作、HDR 误判或显示器硬件故障。

微软明确说明 Gamma 可能被系统或其他程序覆盖，并会在很多显示事件（如连接／断开、分辨率变化）后重置：[SetDeviceGammaRamp](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-setdevicegammaramp)。这支持重置路径的技术可能性，不证明本机某次事件的唯一原因。

## 代码链路

1. `WellbeingCoordinator.SessionChanged` → `ColorTemperatureService.SetSuspendedAsync(true)`。暂停后的 RefreshCore 直接返回，不恢复颜色、不撤销资格，旧恢复记录继续存在。
2. 解锁进入 `ApplyAsync`：当前值只要不等于 `record.LastApplied`，即调用 `Conflict`。这里未单独识别“与已记录 Baseline 完全相同”；`Conflict` 持久化标记并阻止后续自动处理。
3. `RestoreAsync` 和手动 `RecheckOriginalAsync` 本来能够识别精确 Baseline，说明日常恢复路径与手动恢复路径的处理存在差异。
4. UI 将 Conflict、RecoveryPending、Failed 归为需处理恢复记录，并从可编辑的已验证屏幕集合移除。用户看到的是处理入口，不等于验证文件被删除。
5. 用户确认“重新建立原色”后，程序才会归档旧记录、撤销该屏资格并要求重新验证。因此反复重建会增加一整轮验证，锁屏本身不会自动删除资格。
6. 独立边界：验证匹配要求 HardwareId、物理 ScopeId、DeviceName、TopologyFingerprint、ModeFingerprint 全部一致；模式包含显卡 LUID/source id、模式字节等，拓扑又包含全部屏幕。另有瞬态读写失败进入 `_failed` 后不会主动重试的缺口，但本次归档明确是 Conflicted，不能把所有候选都当作本次已证实触发原因。

## 建议的后续修复

- 解锁／重连后先等待连接与读数稳定，区分“上次暖色仍在”“已经回到记录原色”“未知颜色”三个状态。
- 在已验证、身份及受支持模式精确匹配、稳定读回与记录原色完全相同的前提下，耐久完成旧接管记录的恢复，再恢复已保存作息；保留验证资格，不让用户重建原色。不把任意当前颜色当作新原色，也不自动清除已有无法确认的冲突。
- 将临时离线／系统编号变化与真实显示模式变更分开呈现。涉及硬件寻址的精确检查继续保留；任何验证作用域兼容改动都要另行覆盖多屏独立性、HDR、复制、远程及未知身份测试。
- 为有界的连接恢复重试补充明确状态反馈，避免一次瞬态读失败长期卡住；真正未知外部改色仍停止竞争。
- 补充锁屏后系统复原、原值未变、未知外部颜色、多屏依次上电、连接变化后恢复及存储失败回归，再提供独立测试包实测。不能把模拟结果等同于过夜真实验收。
