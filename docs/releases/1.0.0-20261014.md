1. 从旧版托盘菜单选择「退出」，等待退出及亮度／原色恢复完成；只关闭设置窗口不等于退出。
2. 将新 ZIP 完整解压到新目录，保留旧目录，并备份整个 Data 文件夹。
3. 如需保留这台电脑的设置，在两份程序均已退出时，把旧程序旁的**完整 Data 文件夹复制**到新 ScreenKeeper.exe 旁。正确位置为 `ScreenKeeper/Data/ScreenKeeper/`，须一并保留恢复记录、验证记录和图片。
4. 从新目录启动 ScreenKeeper.exe，核对 VERSION.txt 为 1.0.0／20261014。旧快捷方式仍可能指向旧版；如果启用了开机启动，在新程序的通用设置中关闭后重新开启，使其指向新位置。

不要同时运行两份程序、运行时覆盖文件、只复制 settings.json，或使用其他电脑的恢复记录。仍有恢复提示时先按客户端步骤处理，不删除记录以绕过保护。需要回退时也先正常退出并确认恢复，保留最新完整 Data 的备份，不用旧记录覆盖尚未完成的恢复状态。

便携数据保存在 EXE 旁的 Data\ScreenKeeper。向其他用户分发原始 ZIP，不附带自己的 Data。包内附中英双语使用说明、14 组 FAQ、产品与第三方许可。

# ScreenKeeper 1.0.0

Stable portable edition · Build 20261014. Earlier 1.0.0 builds are retained and distinguished by build date and checksums.

## Download and run

Use ScreenKeeper-1.0.0-Portable-x64.zip on 64-bit Windows 10/11, or ScreenKeeper-1.0.0-Portable-x86.zip on 32-bit Windows 10. Windows 11 has no 32-bit OS edition.

Extract the complete ZIP, open ScreenKeeper, and run ScreenKeeper.exe. The .NET runtime is included. Keep all accompanying DLLs and do not launch from inside a ZIP viewer. The Website link at the top of the application opens https://screenkeeper.skyrrats.com/ in your default browser.

## Fixes

- Fixed recursive display selection and preview cancellation when a color display becomes unavailable, which could cause a stack-overflow crash.
- Fixed incorrect HDR/advanced-color blocking on some recent Windows versions while the display is actually in SDR. Active advanced color, unknown states and recovery conflicts still retain their safeguards.
- Both architectures use the same source. Application and test inputs match the user-accepted x64 test build 20261009.3. Existing features and data formats are unchanged.

The user reported no problems during validation of that test build. This does not claim to resolve every exit cause or display connection problem. No fix is claimed for a secondary display being disabled in NVIDIA Control Panel. External color software, drivers and display connection changes may still affect color or validation state.

## Updating from an older or test build

1. Exit the old copy from its tray menu and wait for shutdown and brightness/color restoration. Closing settings only hides the window.
2. Extract the new ZIP into a new folder. Retain the old folder and back up its entire Data folder.
3. To keep settings on this PC, with both copies closed, COPY the entire old Data folder beside the new ScreenKeeper.exe. The result is `ScreenKeeper/Data/ScreenKeeper/`. Keep recovery records, validation records and images together.
4. Start from the new folder and check VERSION.txt for 1.0.0 / 20261014. Old shortcuts may still start the previous build. If startup is enabled, turn it off and back on in the new application's general settings so it points to the new location.

Do not run both copies, replace files while running, copy only settings.json, or reuse another PC's recovery data. Follow outstanding recovery prompts without deleting records. Before reverting, also exit normally and confirm restoration. Keep a complete current Data backup; do not overwrite unresolved recovery state with old records.

Portable data is stored in Data\ScreenKeeper beside the EXE. Share the original ZIP without personal Data. Bilingual instructions, 14 FAQs, product and dependency licenses are included.

## Validation and identity

The release checks cover x64/x86 automated tests, archive integrity, actual architecture, self-contained runtime loading and UI resources; project task 015 records the exact results. The x64 fixes have user feedback. Earlier x86 usage was on a 64-bit Windows PC; the new automated checks are not a new physical-device acceptance test. Native 32-bit Windows 10 remains untested, and display controls depend on hardware and drivers.

The executable is unsigned; Windows may show an unknown-publisher warning. Disabling protection is not required. ScreenKeeper-1.0.0-SHA256SUMS.txt checks file integrity, not publisher authenticity.

VERSION.txt, BUILD-INFO.json and the source manifest identify this exact 1.0.0 / 20261014 snapshot. Historical tags and delivered packages remain unchanged. These local artifacts have not been uploaded to the website or a distribution platform.
